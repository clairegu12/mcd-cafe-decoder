# ☕ 麦咖解码器 · mcd-cafe-decoder

> 麦当劳会告诉你一杯咖啡多少钱，但从不告诉你 **那杯「咖啡」里究竟有多少是咖啡**。

基于麦当劳中国官方 MCP Server，把每一款麦咖啡拆成「几份浓缩 + 几份奶」，再除以**你真正付得出去的价格**，算出「每元咖啡当量」。

```
🍼 冰奶铁中杯（¥21）  =  1.02 份浓缩  +  0.60 份牛奶   →  91.0% 的热量来自牛奶
🖤 冰美式中杯（¥19）  =  1.00 份浓缩  +  0.00 份牛奶   →   0.0% 的热量来自牛奶
```

**同一家店，同一份 1.00 的浓缩，美式收你 19，奶铁收你 21——你多付的 2 块钱，买的全是奶。**

---

## 项目介绍

**麦咖解码器**是一个基于麦当劳中国官方 MCP 的饮品成分分析 Skill。它回答一个官方永远不会直接告诉你、但可以被算出来的问题：

> 这杯麦咖啡里，究竟有几成是咖啡？我为「提神」这一部分，到底付了多少钱？

做法是：把官方公布的营养数据当作可观测向量，构建「一杯饮品 ≈ a × 浓缩咖啡 + b × 奶基底」的双基底混合模型，用非负最小二乘在五个营养维度上解卷积；再把解出来的咖啡当量，除以**你在这个门店、这个时刻真正付得出去的价格**。

输出三项指标——**咖啡当量**（几份浓缩）、**奶占比**（牛奶贡献了多少热量）、**每元咖啡当量**（提神性价比）——外加一张把它们放在一起看的散点图。

它刻意保留了一条让自己可以被证伪的路径：**阴性对照自检、出界剔除、数据源缺陷披露**。这三条中任何一条失守，脚本会明确告诉你结论作废，而不是硬输出一个听起来流畅的答案。

## 三个结论

### 01 · 整条麦咖啡产品线，几乎都是同一份浓缩

把 15 款核心咖啡产品全部解卷积，咖啡当量落在 **0.66 – 1.21 份**之间（中位数 **1.03**）。

差距来自杯型，不来自品类。也就是说——**美式与奶铁的提神效果基本没差别，你多付的钱买到的是奶。**

| 饮品 | 咖啡当量 | 奶占比 | 热量 |
|---|---:|---:|---:|
| 冰美式小杯 | 0.72 | 5.3% | 10 kcal |
| 冰美式中杯 | 1.00 | 0.0% | 13 kcal |
| 冰美式大杯 | 1.05 | 2.7% | 14 kcal |
| 冰奶铁中杯 | 1.02 | 91.0% | 148 kcal |
| 卡布奇诺中杯 | 1.06 | 91.8% | 167 kcal |
| 冰燕麦奶铁中杯 | 0.94 | 90.8% | 132 kcal |

### 02 · 所有的奶咖，九成以上热量来自牛奶

14 款奶咖（奶铁 / 燕麦奶铁 / 卡布奇诺 / 焦糖玛奇朵）的奶占比全部落在 **89% – 94%**，而美式全在 **5% 以下**。

一杯 ¥21 的奶铁，你为咖啡付了不到 2 块钱。

### 03 · 同一杯存在两条价格通道，最多差 2.32 倍

官方 `query-meals` 的返回里，`originalPrice` 与 `currentPrice` 是两个字段，而它们之间隔着一道门槛：

```json
"507409": {
  "name": "麦咖啡™奶铁",
  "currentPrice": "9.9",
  "originalPrice": "21",
  "discountType": "随单购麦金卡优惠",
  "canWithOrder": true        ← 不随单购这张卡，9.9 你拿不到
}
```

| 饮品 | 门店原价 | 随单购麦金卡价 | 提神性价比 |
|---|---:|---:|---:|
| 冰燕麦奶铁大杯 | ¥23 | ¥9.9 | **×2.32** |
| 冰奶铁大杯 | ¥21 | ¥9.9 | ×2.12 |
| 冰美式大杯 | ¥19 | ¥9.9 | ×1.92 |

全场 18 款 SKU 有这条通道。而 `canWithOrder=true` 这道门槛，**并不写在菜单价格旁边**——只看 `currentPrice` 的人会得出完全错误的结论。

> 顺带一提：鲜萃咖啡 ¥9.5，鲜萃冰咖 ¥11.5。**同一款产品，加冰贵 2 元。**

## 它是怎么算出来的

### 核心：五维非负最小二乘解卷积

把一杯奶咖建模为两个已知基底的线性组合：

```
一杯饮品  ≈  a × 浓缩咖啡  +  b × 奶基底
```

其中五个维度同时参与拟合：**能量 / 蛋白质 / 脂肪 / 碳水 / 钙**。
（钠被有意排除：它受水质与蒸汽影响大，对区分咖啡与奶没有贡献。）

`a` 就是**咖啡当量**，`b` 就是**奶当量**，两者都不是拟合出来的噱头，而是有明确物理含义的配比系数。

### 两个基底怎么选

- **咖啡基底**：`浓缩咖啡`（13 kcal / 蛋白 1g / 碳水 2g / 钙 7mg）
- **奶基底**：**必须**取门店「同产品线、同温度」的纯奶，不能用零售盒装奶

第二条是本算法最容易翻车的地方，见下方「为什么用普通最小二乘」一节里的实测对比。

### 三条防线，保证结论不是拟合噪声

**① 阴性对照（模型的自检开关）**

门店纯奶的其他杯型（热牛奶大杯/小杯、冰牛奶大杯/小杯、燕麦奶各杯型）和纯茶，**成分里确实没有咖啡**。如果把它们也解出咖啡当量，说明模型在拿噪声拟合，全部结论作废。

> 实测结果：10 款阴性对照，最大咖啡当量 **0.117 份** → ✅ 通过

**② 出界剔除（承认模型有边界）**

模型是二组分，含第三种配料（蔗糖 / 可可 / 抹茶 / 冰淇淋）的饮品天然解释不了。判定条件有两条，**缺一不可**：

- 残差 > 0.12
- **或** 咖啡当量 > 4 份 ← 这条不能省

> 「浓浓黑巧雪冰大杯」（444 kcal）残差只有 0.07，看着拟合良好，
> 但 NNLS 为配平能量会解出 **33 份咖啡当量**——纯靠残差阈值根本抓不住。
> 全场共剔除 16 款，包括柠檬红茶、热朱古力、抹茶系列、阿芙佳朵、全部雪冰。

**③ 数据撞车披露（主动承认官方数据的缺陷）**

> ⚠️ 官方营养表里，有 **19 个条目**的五维数值与另一款完全不同的产品**一字不差**：
>
> | 条目 | 与之完全等同的条目 |
> |---|---|
> | 热浓浓黑巧大杯 | 热牛奶大杯 |
> | 冰浓浓黑巧大杯 | 冰牛奶小杯 |
> | 热浓浓燕麦黑巧大杯 | 热燕麦奶大杯 |
> | 冰焦糖玛奇朵 | 冰奶铁中杯 |
>
> 这说明这些 SKU **并未单独公布配方**，而不是它们真的没加咖啡。
> 本项目因此把它们标记为 `data_collision`，**不作为独立的结论输出**。

### 为什么用「普通最小二乘」而不是加权

官方营养数据按整数发布（蛋白 8g、钙 251mg），**舍入噪声在绝对单位上近似同方差**，所以 OLS 本身就是统计上正确的估计量。实测对比了四种方案：

| 加权方案 | 阴性对照的最大咖啡当量 | 结论 |
|---|---:|---|
| 相对误差 + 地板 5 | 0.430 | ✗ 在拟合噪声 |
| 相对误差 + 地板 15 | 0.473 | ✗ 在拟合噪声 |
| 按奶基底归一化 | 0.452 | ✗ 在拟合噪声 |
| **绝对单位 OLS** | **0.064** | ✅ 通过 |

一旦按相对误差加权，蛋白质、脂肪这种小量级维度会被地板值放大，拟合就跑去配不舍入噪声了。OLS 下结果也才物理自洽：**冰奶铁中杯 1.02 与 冰美式中杯 1.00——同是那份浓缩，只差奶量。**

## 附加发现：早餐有时间锁

`query-nearby-stores` 返回的 `reservationTimeOptions` 里藏着各店各自的供餐时段。实测上海人民广场周边 5 家店：

| 门店 | 早餐窗口 |
|---|---|
| 黄浦华旭国际大厦餐厅 | 05:14 – 10:15 |
| 雅居乐餐厅 | 06:14 – 10:15 |
| 福州路餐厅 | 06:44 – 10:15 |
| 食品一店餐厅 | 06:44 – 10:15 |
| 南京西路 NX258 餐厅 | 07:14 – 10:15 |

**开门时间逐店相差整整 2 小时，关门时间却在 10:15 高度统一。** 而 9.9 元早餐组合（含鲜萃咖啡）只在这个窗口内有效——最便宜的咖啡通道是有硬截止时刻的，官方从未单独文档化这件事。

## 目标用户 · 适合谁用

| 你是 | 你会拿它做什么 |
|---|---|
| 咖啡因刚需的打工人 | 弄清楚贵一倍的奶铁到底比美式多给了你什么（答案是：奶） |
| 在乎性价比的人 | 看清楚菜单上那个 9.9 是有门槛的，进而在两条通道之间做真实比较 |
| 在纠结要不要买麦金卡的人 | 用实际双通道价差算临界杯数，而不是凭感觉 |
| 减脂 / 控糖的人 | 在「提神」与「热量」之间做有依据的取舍（两者分布几乎正交） |
| 做数据分析的人 | 一个完整的、可证伪的解卷积案例：阴性对照 + 出界剔除 + 数据源缺陷披露 |

> ❌ **不适合**：想知道精确咖啡因毫克数的人。官方不公布咖啡因，本项目的「咖啡当量」是**相对指标**，横向比较有效，不等于咖啡因含量。

## 快速开始

### 依赖

- Python 3.9+（标准库即可，**无需 pandas / numpy / scipy**）
- 已配置好的麦当劳中国官方 MCP Server `mcd-mcp`

MCP 配置示例（`~/.workbuddy/mcp.json`）：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": { "Authorization": "Bearer <你的Token>" }
    }
  }
}
```

Token 到 https://open.mcd.cn/mcp 用手机号登录后申请（每分钟限 600 次请求）。

### 运行

仓库已内置一份真实取数快照，不联网也能跑通：

```bash
git clone https://github.com/<你的账号>/mcd-cafe-decoder.git
cd mcd-cafe-decoder

python scripts/analyze_cafe.py            # 生成 data/cafe_index.json
python scripts/render_web.py              # 生成 web/index.html
```

然后**双击 `web/index.html`** 即可打开可视化结果（单文件、零 CDN 依赖、可离线）。

### 想换成你自己城市的门店

把 `data/*.json` 换成新取数即可，字段结构保持一致：

| 文件 | 来源 |
|---|---|
| `data/nutrition.csv` | `list-nutrition-foods` |
| `data/menu_cafe.json` | `query-meals`（麦咖啡™ 与 饮品 两个分类） |
| `data/stores.json` | `query-nearby-stores` |

| 字段 | 含义 |
|---|---|
| `espresso_equiv` | 咖啡当量（份浓缩） |

| `milk_ratio` | 牛奶提供了多少比例的热量 |
| `cafe_per_yuan_original` / `_card` | 两条价格通道下的每元咖啡当量 |
| `has_card_channel` / `card_gate` | 是否存在卡通道，以及门槛类型 |
| `fit_residual` / `out_of_model` | 拟合质量与是否已剔除 |
| `data_collision` / `data_collision_with` | 是否与官方其他条目数值撞车 |

## 已知边界

- 部分 SKU（焦糖玛奇朵、抹茶牛奶、阿芙佳朵）在该门店菜单上不存在，只有营养数据没有价格，落在排行榜之外。
- 菜单接口未暴露分杯型定价，同一 `menu_code` 下的小/中/大杯按同一价格处理。
- 价格与菜单**具门店与时效性**：以上数据取于 2026-10-10 01:13，麦当劳上海黄浦华旭国际大厦餐厅（`storeCode=1450713`）。换门店、换时间都可能变化。
- 「咖啡当量」是相对指标，不是咖啡因毫克数。
